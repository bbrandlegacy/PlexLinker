# Script Generation & Auto-Execution Feature Summary

## Overview
PlexLinker now generates scripts directly in the destination directories and auto-executes them with proper directory context.

---

## How It Works

### 1. Script Output Location
**Before:** Scripts were generated in temp directory (`/tmp` or `%TEMP%`)
**After:** Scripts are generated in the same directory as the PlexLinker executable

**Example:**
```
Executable location: C:\Users\username\plexlinker.exe
Script output: C:\Users\username\plexhelper_movies.bat
```

**Benefits:**
- Easy to find scripts (same folder as the program)
- Scripts persist after reboot (not in temp)
- Can re-run scripts anytime

### 2. Path Resolution
The system automatically resolves "auto" paths to platform-specific defaults:

| Config Value | Windows Output | Unix/WSL Output |
|--------------|----------------|-----------------|
| `"auto"` or `""` | `W:\movies` | `/w/movies` |
| `"W:\custom"` | `W:\custom` | `W:\custom` |
| `"/custom"` | `/custom` | `/custom` |

**Implementation:** `internal/paths/defaults.go:ResolveAutoPath()`

### 3. Script Content
Each generated script includes:

**Windows Batch (.bat):**
```batch
@echo off
REM aria2c download script for movies - generated by PlexLinker
REM Generated on: 2025-10-09 12:00:00

cd /d "W:\movies"

aria2c -x4 --http-user username --http-passwd password "https://...";
aria2c -x4 --http-user username --http-passwd password "https://...";

echo All downloads completed!
pause
```

**Unix Shell (.sh):**
```bash
#!/bin/bash
# aria2c download script for movies - generated by PlexLinker
# Generated on: 2025-10-09 12:00:00

cd '/w/movies'

aria2c -x4 --http-user username --http-passwd password "https://...";
aria2c -x4 --http-user username --http-passwd password "https://...";

echo 'All downloads completed!'
read -p 'Press Enter to close...'
```

### 4. Auto-Execution Flow

```
┌─────────────────────────────────────────┐
│ User presses '5' (Generate Script)      │
└────────────────┬────────────────────────┘
                 │
                 ▼
┌─────────────────────────────────────────┐
│ Script Generator Preview Window         │
│ - Shows file categorization             │

│ - Allows TV show folder selection       │
└────────────────┬────────────────────────┘
                 │
                 ▼ User confirms

│ 1. Resolve "auto" paths                 │
│ 2. Create output directory if needed    │

└────────────────┬────────────────────────┘
                 │
                 ▼

                 │
                 ▼

│ Script Runs in New Window               │
│ 1. cd to destination directory          │
│ 2. Run aria2c downloads                 │
│ 3. Files saved to current directory     │
│ 4. Pause for user review                │
└─────────────────────────────────────────┘
```

## Code Changes

### File: `internal/downloader/generator.go`

#### Change 1: Path Resolution (Lines 152-161)
```go
// Resolve "auto" paths to actual platform defaults
moviesPath = paths.ResolveAutoPath(moviesPath, "movies")
tvShowsPath = paths.ResolveAutoPath(tvShowsPath, "tvshows")
otherPath = paths.ResolveAutoPath(otherPath, "other")

// Use the resolved destination directory for script output
scriptDir := moviesPath
if scriptDir == "" || scriptDir == "auto" {
    scriptDir = os.TempDir()
}
```

**Why:** Converts "auto" to platform-specific paths before generating scripts

#### Change 2: Output Directory Creation (Lines 246-249)
```go
// Create output directory if it doesn't exist
if err := os.MkdirAll(outputDir, 0755); err != nil {
    return "", fmt.Errorf("failed to create output directory: %v", err)
}
```

**Why:** Ensures destination directory exists before writing script

#### Change 3: Script Path Construction (Line 251)
```go
scriptPath := filepath.Join(outputDir, scriptName)
```

**Why:** Uses destination directory instead of temp directory

### File: `internal/ui/script_generator.go`

#### Change 1: Added Logging (Lines 152, 155, 160)
```go
logger.Get().Main().Printf("Executing script: %s", scriptPath)
// ... execution ...
logger.Get().Main().Printf("Successfully launched script: %s", filepath.Base(scriptPath))
```

**Why:** Debug visibility for script execution

#### Change 2: Enhanced Status Messages (Lines 165-167)
```go
scriptDir := filepath.Dir(scriptPaths[0])
state.statusMessage = fmt.Sprintf("Generated %d script(s) in %s and launched %d",
    len(scriptPaths), scriptDir, successCount)
```

**Why:** User sees exactly where scripts were saved

## User Experience

### Before This Feature:
1. User selects files and generates script
2. Script saved to `/tmp/plexhelper_movies.bat`
3. Script auto-runs but user doesn't know where it is
4. Downloads go to temp directory
5. User must manually move files to correct location

### After This Feature:
1. User selects files and generates script
2. Script saved to `C:\Users\username\plexhelper_movies.bat` (same folder as plexlinker.exe)
3. Script auto-runs in new window
4. Script changes to `W:\movies` directory before downloading
5. Downloads go directly to `W:\movies`
6. Status shows: "Generated 1 script(s) in C:\Users\username and launched 1"
7. Script remains available for re-running later

## Configuration Example

### plexlinker.json
```json
{
  "base_url": "https://example.com/media/",
  "username": "user",
  "password": "pass",
  "script_format": "bat",
  "debug_mode": false,
  "movies_path": "auto",
  "tv_shows_path": "auto",
  "other_path": "auto"
}
```

### Resulting Behavior:
Scripts are saved in the same directory as the plexlinker executable:

- **Windows:**
  - If plexlinker.exe is at: `C:\Users\john\plexlinker.exe`
  - Scripts saved to: `C:\Users\john\plexhelper_movies.bat`
  - Scripts run `cd /d W:\movies` before downloading

- **Unix/WSL:**
  - If plexlinker is at: `/home/john/plexlinker`
  - Scripts saved to: `/home/john/plexhelper_movies.sh`
  - Scripts run `cd /w/movies` before downloading

## Security Considerations

### File Permissions
- Scripts created with `0755` (rwxr-xr-x)
- Config recommends setting to `0600` for credentials security
- Output directories created with `0755`

### Credential Handling
- Credentials embedded in script (by design)
- User should secure scripts after generation
- Alternative: Use aria2c `.netrc` file (future enhancement)
